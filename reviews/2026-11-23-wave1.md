## 3. BLOCKING (fix before release)

1. **CFD flies the aircraft backwards.** cfd.py:177,184,229-233,512 and `_flow` cfd.py:372-399 use the K09-L x-aft
   convention on an x-forward aircraft. Fix: make the freestream come from +x. Use `ux = -V cos α`, `uz = +V sin α`,
   upstream `hi[0] + UP_L*L`, downstream `lo[0] - DOWN_L*L`, the wake box from `lo[0] - 2.5L` to `hi[0]`,
   locationInMesh ahead of the nose, `drag_d = [-cos α, 0, sin α]`, `lift_d = [sin α, 0, cos α]`, and streamline
   seeds at `hi[0] + 0.3L`. A simpler alternative: rotate the geometry 180° about z when writing the STL (a proper
   rotation, so winding is kept) and rotate the fields back. Add to test_cfd_case_dictionaries: the upstream
   boundary is ahead of the nose, and U·x̂_forward < 0.
2. **Estimate-based "ok" shown as "Good".** structure.py:341, cfd.py:550 and flight.py:302-307 return `ok` while
   their basis is `estimate`. mass and propulsion return `conditional`. Fix in one place, pipeline.py after
   line 196: if `res["status"] == "ok"` and any metric basis contains `estimate`, set `conditional`. In dash.js:39,
   rename `ok` to "Computed" (not "Good"), or show the basis chip on every card. Add a test that no result is `ok`
   on estimate inputs.
3. **Stale CFD served as cached.** `cfd.NEEDS` (cfd.py:29-30) leaves out `geometry.units`, `geometry.forward`,
   `geometry.up` and `roles`, and CFD has no dependencies. Changing units or roles reuses the old result, and
   `status` does not mark it stale. Fix: add `"geometry", "roles"` to `cfd.NEEDS`, plus a cache test that changes
   `geometry.units`.
4. **`opencae new` → `run` is broken for agents.** pipeline.py:300 returns `…/drone.json`; cli.py:126-135 uses it
   as the project folder. Fix: return `directory` from `new_project`, as the brief says (`-> Path` project dir),
   and drop the `out.parent if out.is_file()` workaround in new_dialog.py:109. Also make `_project`
   (cli.py:67-73) accept a drone.json path by taking `.parent`, catch `OSError` in `main` → exit 2, and fix the
   text at cli.py:135 ("every property starts empty (null)").
5. **Cross-origin writes to drone.json (CSRF / DNS rebinding).** server.py:481-490. Fix: in `do_GET` and
   `do_POST`, reject a `Host` header other than `127.0.0.1:<port>` or `localhost:<port>` (403). In `do_POST`,
   require `Content-Type: application/json`, which forces a CORS preflight that the server never answers, and
   reject any `Origin` other than the server's own. Tighten `_VARIANT_RE` to `^[A-Za-z0-9_][A-Za-z0-9_.\-]{0,79}$`
   with no `..`. Add a test: a text/plain or foreign-Origin POST gets 403 and drone.json is unchanged.
6. **Aircraft frame is mirrored.** geometry.py:289 builds y = up × forward, which is *left* for a right-handed CAD
   file. Everything downstream assumes y right: dash.js:62 `toThree`, the y-mirroring in cfd.py:106 and in
   flight.py, and docs/DRONE_PROJECTS.md:78. A real STEP/STL is therefore shown and simulated as its mirror
   image. quad250 hides this because its STL was authored left-handed (make_geometry.py:3,61). Fix: make the
   frame right-handed (x forward, **y left**, z up) and correct the docs. Then remove `_mirror_y`/`_flip_y` in
   cfd.py and the y-mirror in flight.py, change `toThree` to `[x, z, -y]`, and regenerate quad250 with front-left
   at +y. Test: a part at CAD +y with forward +x, up +z lands at aircraft +y, labelled left.
7. **Dashboard iterations cannot be stopped and lose progress.** server.py:353-357 vs pipeline.py:308. Fix: add
   `progress=None, cancelled=None` to `pipeline.iterate` and pass them to both `run_project` calls. Then remove the
   `except TypeError` fallback, which also silently reruns a job that failed with a TypeError.
8. **Known dashboard defects (conductor), confirmed in code:**
   (a) JS error `reading 'children'`: buildModel (dash.js:122) touches `modelGroup` before the `!S.geo` guard,
   and before checking that initScene succeeded. Fix: `if (!modelGroup) return;` first, then the `!S.geo` check.
   (b) No 3D model before the first run: `/api/geometry` 404s until a run writes geometry.npz (server.py:257-263).
   Fix: when it is missing, build it on demand with `geometry.load` + `save_npz` into `results/baseline/`.
   (c) CFD slices drawn as scattered points (dash.js:376-383). Fix: build a `THREE.Mesh` from `slice_triangles`
   (indices are already offset), with vertex colours and `DoubleSide`.
   (d) Solid prop discs hide the airframe (dash.js:36). Fix: role `prop` gets `transparent: true, opacity: 0.25,
   depthWrite: false`.
   (e) Workflow bar visible in Drone mode. Fix: hide or show `self.workflow`'s toolbar in `_on_mode_changed`
   (main_window.py).
   (f) Parameter names cut off in the app sheet. Fix: set the name column to `ResizeToContents` or add tooltips.

## 4. NON-BLOCKING

1. Use one shared input reader. cfd.py, structure.py and flight.py each copy `_leaf/_num/_weakest/RANK`, and their
   RANK puts `user` equal to `measured` while spec.py puts it above. Use `spec.param`/`spec.basis`/`spec.weakest`
   and delete about 60 lines.
2. CFD storage: write one `cfd_surface.npz` that holds `cp, p_static, u_near_wall, wall_shear` over one set of
   points and triangles. dash.js already picks `d[key]`. Cast slice and stream points to float32 and values to
   float16 before `save_field`. That saves about 1 MB of the 1.7 MB per run.
3. State the remaining defaults where the user sees them: V_CELL 3.7 V nominal (or make
   `propulsion.battery.cell_voltage` a key); the payload left out of the CG (mass.py:91); the rho fallback in
   cfd/propulsion (use `not_evaluated`, since the template always has rho). Write the template's rho, g, alpha 0,
   load_factor 2, disturbance 15 and payload 0 as `{"status": "user", "source": "default choice, change if needed"}`.
4. structure summary "safety factor … at 2 g" (structure.py:343): the load is 2 × max thrust, not 2 g. Say
   "at 2 × full thrust".
5. Cancelling or closing the app does not stop a running OpenFOAM step (cfd.py:89 `subprocess.run`). Use `Popen`
   and poll `ctx.cancelled()`, then kill the process group (`taskkill /T` on Windows). Call this from
   `DashboardServer.stop()` before the app exits.
6. pyproject `package-data`: add `"examples/drones/**/*"`.
7. The dashboard keeps its own `BETTER` and compare logic (dash.js:50,567-575) next to `pipeline.BETTER` and
   `iterate()`'s `compare`. Keep one: serve `BETTER` through `/api/project`, or store `compare` in the variant's
   results.json.
8. flight.py:326: output `pos/att` in the project frame, in degrees as the contract says, and remove the unit
   guessing in dash.js:434-437.
9. checks.py:18-19: make `ROLE_NEEDS` match structure.py:238 (tailsitter/vtol → `arm`), or change structure to
   match.
10. server.py: remove the dead `ImportError` fallback in `_drone_json` (server.py:220-229) and the
    `hasattr(spec, "validate")` check (server.py:328). The pipeline is now required.
11. CLI: with `--json`, print `{"error": …}` on argparse errors too. Override `ArgumentParser.error`.
12. Could anything be removed? The parameter sheet in the app and the dashboard's Parameters tab edit the same
    file. Consider keeping only the dashboard tab, with a Save path, and dropping the Qt sheet (about 150 lines of
    workspace.py). That would also remove the truncation issue (8f). `_mirror_y` and `_flip_y` go away with B6.
