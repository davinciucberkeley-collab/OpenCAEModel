## 3. Blocking issues (release blockers)

**B1. Chromium's GPU blocklist is switched off by default.** File: `opencae/utilities/crash.py:415-417`.

```python
flags = os.environ.get("QTWEBENGINE_CHROMIUM_FLAGS")
if flags is None:
    os.environ["QTWEBENGINE_CHROMIUM_FLAGS"] = _GPU_FLAGS if safe_mode() else "--ignore-gpu-blocklist"
```
The flag is new in this wave (`git grep` at 2f659ca finds none). On every normal start it tells Chromium to use the GPU on
drivers that Chromium has blocklisted *because they crash*. This lands on the user's Windows PC, whose complaint is
exactly that the app exits with no log.

My understanding, not checked against a source in this review: Qt WebEngine runs Chromium's GPU service inside the
application process. If so, a driver fault takes the whole app down, not just the render process, and
`renderProcessTerminated` cannot catch it. Safe mode would then recover the next start, but the start after that is a
normal one again with the flag back. The new code adds a crash risk to the very symptom this wave is meant to fix.

**Fix:** leave the variable alone in normal mode. Delete the `else "--ignore-gpu-blocklist"` branch, so that only safe
mode adds `--disable-gpu --disable-gpu-compositing`. Add a test asserting that `prepare_qt_environment()` does not set
`QTWEBENGINE_CHROMIUM_FLAGS` when not in safe mode.

**B2. Undoing an evidence-status change can restore a status the row never had.** File: `opencae/ui/drone/workspace.py:561-574`
(`_on_status` / `_status_seen`), with `_apply` at 535-547.

`_status_seen[key]` is updated only by user edits:
- undo and redo go through `_apply` with `_busy=True`, so `_on_status` returns early and the stored value goes stale;
- `load()` never clears it.

Reproduction: change estimate to datasheet, undo (back to estimate), choose measured, undo. The combo shows **datasheet**,
and Save writes it. The evidence status decides whether a requirement may pass ("passes only on measured or datasheet
evidence", AGENTS.md), so undo can silently turn an estimate into datasheet evidence.

**Fix:**
1. In `_apply`, when `kind == "status"`, set `self._status_seen[key] = value`.
2. In `load()`, reset `self.__dict__["_status_seen_d"] = {}`.
3. Better still, drop the property hack: read `old` from a plain dict kept beside `_text`, and remove the always-true
   `hasattr` at 564.
4. Add a test for the sequence above.

## 4. Non-blocking issues (ordered by value)

1. **N1. WebEngine is imported at every start.** File: `crash.py:411-414`, also `main.py:63`. The import adds DLL-load risk and start-up time even for
   Studio-only use. Its comment says the import is "required on Windows", but `AA_ShareOpenGLContexts` (`main.py:66`) already
   meets Qt's condition (workspace.py's own docstring at 38 says so). If the import itself hard-crashes, the result alternates:
   one start crashes, the next is in safe mode, the next crashes again.
   *Fix:* remove the eager import and keep `web_view_allowed()` lazy. Optionally, write a `"phase"` into `session.lock`
   before risky steps ("webengine", "viewport"). A stale sentinel with that phase would then switch the view off until
   the user turns it back on.
2. **N2. Console `set` saves impossible values.** File: `console.py:802-830`. It does not range-check. *Fix:* move
   `limits`/`check_value` (`workspace.py:244-305`) into `opencae/drone/spec.py` and call it from the sheet, the wizard,
   console `set` and CLI `--set`. Use one `set_status(spec, key, status)` there for both the sheet and the console.
3. **N3. A stopped run is reported as finished.** Files: `server.py:193-205`, `tracker.py:293-297, 349-354`, `console.py:600-604`.
   It shows "Done/Finished, 100 %, verdict …". *Fix:* in `body`, set `err = "Stopped."` when `self._cancel.is_set()` or
   `(res or {}).get("cancelled")`. Alternatively, keep the `run_done` event's `status` in `progress` and drive the labels
   from it.
4. **N4. F1 is ambiguous on the Drone page.** File: `ux.py:335`. *Fix:* add `"guide"` to `CONFLICTING`. Also add a test that
   presses F1, F5 and Ctrl+Z on the Drone page and checks that exactly one handler runs.
5. **N5. The "keep solver files" path bypasses events and the server's checks.** File: `workspace.py:1365-1366, 1380-1388`.
   *Fix:* add `keep_cases` to the body that `DashboardServer.run` accepts, which passes `events=self.jobs.on_event`. Then
   delete `_start_keep_run`.
6. **N6. Tests write the real QSettings.** Files: `workspace.py:858-889`, `ux.py:397-400`, `main_window.py:1375`.
   *Fix:* give `DroneWorkspace(parent, start_server, settings=None)` a settings argument, have `drone_workspace()` pass
   `self.settings`, and delete the `sync` injection. In `conftest.py`, call
   `QSettings.setPath(QSettings.IniFormat/NativeFormat, UserScope, tmp)` or set `XDG_CONFIG_HOME` for the session.
7. **N7. The session sentinel uses pid liveness.** File: `crash.py:151-199`. On Windows this has the pid-reuse and
   access-denied problems (W1). *Fix:* hold an OS lock on `session.lock` for the life of the process with
   `msvcrt.locking` / `fcntl.flock`, as in `drone/runlock.py:20-45`. A lock that can be taken means the previous run died;
   a lock that is held means another instance is running. Also treat `KeyboardInterrupt` in `main.py:54` as a clean exit.
8. **N8. The "Leave safe mode (next start)" button does nothing.** File: `workspace.py:1059-1061`. The next start is
   decided by the sentinel, so the button has no effect. *Fix:* remove it, or make it rebuild the view now (swap the
   fallback for a new `QWebEngineView`).

   **Related: the software-3D claim is not true for the viewport.** `safe_mode_notice` (`crash.py:145-147`) says
   "3D graphics use software rendering if needed". The VTK viewport is `pyvistaqt.QtInteractor` (`viewport.py:16, 84`),
   which makes its own WGL context, so `AA_UseSoftwareOpenGL` / `QT_OPENGL=software` do not reach it. *Fix:* reword the
   notice, or delay the viewport in safe mode.
9. **N9. Fragile version detection.** File: `qt_guard.py:55-62`, also `crash.versions()`. *Fix:* use `PySide6.__version__`
   or `shiboken6.__version__` (importing the package creates no Qt object), with metadata as a fallback.
10. **N10. ETA is misleading at the start of a run.** File: `server.py:115-134`. It counts cached analyses at their typical
    time, and it uses coarse-preset CFD history for a fine run. *Fix:* key the typical durations by `(aid, preset)`. Either
    leave out analyses whose cache key is unchanged (`pipeline.status(...)[...]["stale"]` is already computed), or show
